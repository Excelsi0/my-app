# Контракты и классификация проверок

## Ожидаемые endpoints

| Имя | URL | Авторизация | Ожидаемый корень |
| --- | --- | --- | --- |
| `finance1` | `https://cpa-server-vtel.onrender.com/api/finance1` | `x-api-key` | объект с `transactions` |
| `finance2` | `https://cpa-server-vtel.onrender.com/api/finance2` | `x-api-key` | массив строк |
| `rates` | `https://api.currencyfreaks.com/v2.0/rates/latest` | query `apikey` | объект с `rates` |

## Finance 1

Ожидаемая форма:

```json
{
  "transactions": [
    { "type": "paid", "amount": 100.25, "currency": "USD" }
  ]
}
```

Правила:

- `transactions` — массив;
- элемент — объект;
- `type` — строка; каноническое оплаченное значение — `paid`;
- `amount` — конечное JSON-число;
- `currency` — трёхбуквенный ISO 4217 code в верхнем регистре.

Non-`paid` значения не являются ошибкой сами по себе: они не входят в расчёт выручки. Разный регистр и пробелы вокруг одного статуса являются проблемой консистентности.

## Finance 2

Ожидаемая форма:

```json
["680 USD", "120.50 EUR"]
```

Канонический элемент — строка `<положительное число> <ISO 4217 code>`, один пробел, точка как десятичный разделитель, валюта в верхнем регистре. Текущий parser приложения принимает только неотрицательные цифры с необязательной дробной частью и три латинские буквы.

## Rates

Ожидаемая форма:

```json
{
  "rates": {
    "EUR": "0.92",
    "RUB": "90.00"
  }
}
```

Ключ — код валюты. Значение может быть числом или числовой строкой, но после преобразования должно быть конечным и больше нуля. Для валют кроме USD ExFlow делит исходную сумму на курс, поэтому отсутствие курса приводит к пропуску операции.

CurrencyFreaks может возвращать crypto и другие non-ISO instrument codes. Само их присутствие не является ошибкой rates API. Аудитор обязан строго проверять ISO 4217 и наличие валидного курса для кодов, фактически встречающихся в `finance1` и `finance2`; остальные keys учитывать только как информационное покрытие provider.

## Подтверждённые проблемы и эвристики

Подтверждённые нарушения:

- недоступный endpoint или не-JSON ответ;
- неправильный корневой тип;
- отсутствующее обязательное поле;
- поле неправильного типа;
- неизвестный ISO code;
- валюта источника без валидного курса;
- сумма или курс `NaN`, infinity, zero/negative там, где требуется положительное значение;
- finance2 string, не принимаемая текущим parser.

Эвристические предупреждения:

- идентичные записи без transaction ID;
- слишком высокая latency;
- более двух десятичных знаков;
- неожиданные дополнительные поля;
- отрицательная `paid` сумма, которая может быть допустимой корректировкой по бизнес-правилам.

В отчёте явно обозначать эвристику и не представлять её как доказанную серверную ошибку.
